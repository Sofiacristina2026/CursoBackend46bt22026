### Parte A ###

**1. Abstração de Dados:** O **PDO (PHP Data Objects)** é uma interface do PHP utilizada para realizar conexões e operações com bancos de dados. Ele é preferível em projetos corporativos porque permite trabalhar com diferentes tipos de bancos de dados usando uma estrutura semelhante, além de oferecer recursos de segurança, como **Prepared Statements**, e um tratamento de erros mais organizado. Já extensões procedurais específicas, como o antigo **pgsql**, são mais dependentes do PostgreSQL.

**2. Ciclo do DSN:** A **DSN (Data Source Name)** é uma string que informa ao PHP os dados necessários para localizar e acessar o banco de dados. No PostgreSQL, o parâmetro **host** indica o endereço do servidor onde o banco está instalado, o **port** informa a porta utilizada para a conexão e o **dbname** indica o nome do banco de dados que será acessado. Um exemplo seria: `pgsql:host=localhost;port=5432;dbname=loja`.

**3. Padrão de Portas:** A porta padrão utilizada pelo **PostgreSQL é a 5432**. Dentro da string de conexão, ela é informada pelo parâmetro **port**, por exemplo: `port=5432`. Dessa forma, o PHP sabe em qual porta deve procurar o servidor PostgreSQL.

**4. Flags de Integridade:** Quando configuramos **PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION**, o PDO passa a lançar uma **exceção (PDOException)** sempre que ocorrer um erro na operação com o banco de dados. Isso facilita o tratamento dos erros através de `try` e `catch`. Caso essa configuração não seja definida, o comportamento padrão do PDO é **PDO::ERRMODE_SILENT**, no qual os erros não são lançados automaticamente como exceções, sendo necessário verificar os erros manualmente.

**5. Fetch Mode:** O **PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC** faz com que os resultados das consultas sejam retornados como **arrays associativos**, utilizando os nomes das colunas como chaves. Isso evita que cada registro tenha também índices numéricos duplicados, reduzindo a quantidade de dados desnecessários armazenados na memória e tornando o consumo de RAM mais eficiente.

**6. Padrão Singleton:** Abrir uma nova conexão utilizando `new PDO()` a cada consulta pode criar várias conexões simultâneas com o banco de dados. O PostgreSQL possui um limite de conexões definido pela configuração **max_connections**. Se muitas conexões forem abertas e não forem reutilizadas ou encerradas corretamente, esse limite pode ser atingido, fazendo com que novas conexões sejam recusadas. O padrão **Singleton** ajuda a reutilizar uma única instância de conexão dentro da aplicação.

**7. Encapsulamento do Singleton:** O construtor da classe **ConexaoBanco** deve ser `private` para impedir que outras partes do programa criem diretamente novos objetos usando `new ConexaoBanco()`. Para garantir a unicidade da instância, também é comum bloquear a **clonagem** com `__clone()` e impedir a **desserialização** com `__wakeup()`. Dessa forma, a classe consegue controlar a criação da única instância da conexão.

**8. Segurança de Credenciais:** Nunca devemos deixar usuário e senha do banco de dados **hardcoded**, ou seja, escritos diretamente nos scripts PHP, porque essas informações podem acabar sendo expostas caso o código seja compartilhado, publicado em um repositório ou acessado indevidamente. O ideal é utilizar **variáveis de ambiente ou arquivos de configuração protegidos**, mantendo as credenciais separadas do código-fonte principal.

**9. Tratamento de Exceções e LGPD:** Exibir diretamente `$e->getMessage()` no navegador pode revelar informações internas do sistema, como **nome do banco de dados, endereço do servidor, caminhos de arquivos, consultas SQL ou detalhes da estrutura do banco**. Isso é considerado uma falha de segurança chamada **Information Disclosure**, pois fornece informações que podem ajudar alguém a explorar o sistema. Além disso, quando existem dados pessoais envolvidos, é importante evitar a exposição desnecessária de informações, seguindo princípios de segurança e proteção previstos pela **LGPD**. Por isso, em um sistema real, o erro deve ser registrado de forma segura nos logs e o usuário deve receber apenas uma mensagem genérica.
